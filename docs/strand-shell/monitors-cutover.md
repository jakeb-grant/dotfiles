# Monitors cutover: hyprpier to Strand

Strand takes over from hyprpier: `strand/monitors.strand` arranges the monitors from
`monitors.toml`, the launcher's Displays page (Alt+Y) saves layouts, and its Thunderbolt page
(Alt+H) lets docks in through bolt. Do the steps in this order, docked at home if you can.

## 1. Strand on edge, then `chezmoi apply`

```sh
curl -fsSL https://strand.jacobgrant.dev/install.sh | sh -s -- --edge
strand --version        # edge, d9d726f4 or later
pkill -f '^strand run'; hyprctl dispatch 'hl.dsp.exec_cmd("strand run")'
git -C ~/.local/share/chezmoi merge --ff-only strand-monitors
chezmoi apply
```

`monitors.strand` needs `d9d726f4` or later, so update Strand first. `chezmoi apply` asks for sudo twice: once for
retiring hyprpier and once for installing `thunderbolt-resume.service`.

Strand reloads `~/.config/strand` on its own and arranges the monitors about 1.5 s later. Strand
won't write over a `monitors.lua` it didn't write, so until the retire script removes hyprpier's,
it tries again every few seconds. That is expected.

## 2. What happens to hyprpier

`run_once_after_retire-hyprpier.sh` runs once during the apply:

- It stops `hyprpier daemon`. Hyprland no longer starts it, because the `exec-once` is gone from
  `hyprland.lua`.
- It removes `~/.config/hypr/monitors.lua` if hyprpier wrote it (its first line is
  `-- Generated by hyprpier`). Strand writes its own in its place, and hyprpier's lid binds go with
  the old file. The lid is now Strand's: the panel goes off while the lid is shut and another
  monitor is on.
- With sudo, it disables and deletes `hyprpier-resume.service` and deletes
  `/etc/udev/rules.d/99-hyprpier.rules`, then reloads systemd and udev.
- `run_onchange_after_setup-thunderbolt-resume.sh` installs `thunderbolt-resume.service` in place
  of hyprpier's. After a resume it still resets the Thunderbolt controllers, but it lets back in only
  the devices bolt let in, not every device.

If you skipped the sudo prompt, or the rule is still there, remove it by hand:

```sh
sudo rm /etc/udev/rules.d/99-hyprpier.rules && sudo udevadm control --reload
sudo systemctl disable hyprpier-resume.service && sudo rm /etc/systemd/system/hyprpier-resume.service && sudo systemctl daemon-reload
```

Then uninstall hyprpier: `yay -R hyprpier-git`. `~/.config/hyprpier` can stay; nothing reads it.

## 3. Enroll each dock

hyprpier's udev rule let every Thunderbolt device in without bolt storing it. Without the rule,
bolt keeps a device it doesn't know out, so enroll each dock once:

- **Plugged in now** (let in by the old rule): Alt+H, select the dock (it reads "this time"), then
  Enter. It now reads "always allowed".
- **Plugged in later, or at work:** a second after you plug it in, the launcher opens on the
  Thunderbolt page with "wants to connect". Enter allows it always (bolt stores it with policy
  auto), Shift+Enter allows it this once, and Esc leaves it blocked.

F2 names a stored dock and Del forgets it. A forgotten dock stays in until it's unplugged, and bolt
asks again at its next plug. Check with `boltctl list`: each dock should show `stored: yes` and
`policy: auto`.

## 4. Check that it worked

- `pgrep -af hyprpier` prints nothing. `/etc/udev/rules.d/99-hyprpier.rules` and
  `hyprpier-resume.service` are gone, and `systemctl is-enabled thunderbolt-resume` says
  `enabled`.
- `head -3 ~/.config/hypr/monitors.lua` says Strand wrote it.
- Alt+Y names the profile: "home" docked at home, "default" undocked, "work" at work. It shows
  "Best guess" for a set with no profile. Workspaces 1-5 sit on the left ASUS and 6-10 on the
  right. `strand get monitors.profile --json` says the same from a terminal.
- Shut the lid while docked: the panel goes off and the focus stays where it was. Open the lid:
  the panel comes back.
- Unplug the dock: the panel takes all ten workspaces. Plug it back in: home comes back without a
  Thunderbolt prompt, now that the dock is enrolled.
- **At work:** the work profile's monitor ids come from hyprpier's profile, and Strand hasn't seen
  those monitors yet. If Alt+Y says "Best guess" and the guess is right (left to right by port, panel
  last), save it with Enter on the profile row and name it "work". If the guess is wrong, fix the
  monitors' places in `state/monitors.toml`. chezmoi's autoCommit commits a save at the next
  `chezmoi` write, or you can commit it by hand. Enroll a work dock
  the same way as in step 3.
- **After a suspend with the dock attached**, which is still the open docked-suspend re-test in
  `dot_config/hypr/README.md`: the dock's USB devices should be back within a few seconds, and
  `journalctl -b -u thunderbolt-resume` shouldn't say "not let back in". The service waits up to
  30 s for bolt to let back in each stored dock that is still plugged in, and 8 s at most for one
  unplugged while asleep. It doesn't wait for a device stored with policy manual.

## 5. Roll back

```sh
cd ~/.local/share/chezmoi
git revert --no-edit 8cc240f..strand-monitors   # every commit of the cutover branch
chezmoi apply
rm ~/.config/strand/monitors.strand ~/.config/strand/monitors.toml ~/.local/bin/bolt-devices ~/.config/hypr/monitors.lua
sudo systemctl disable thunderbolt-resume.service
sudo rm /etc/systemd/system/thunderbolt-resume.service /usr/local/libexec/thunderbolt-resume
sudo systemctl daemon-reload
yay -S hyprpier-git
sudo hyprpier setup && sudo hyprpier setup --resume
hyprpier apply home     # or default / work; writes monitors.lua
hyprctl dispatch 'hl.dsp.exec_cmd("hyprpier daemon")'
```

The revert brings back the launcher without its Displays and Thunderbolt pages, and the `exec-once`
for `hyprpier daemon`. chezmoi doesn't delete files that leave the source, so the `rm` removes
Strand's monitors config by hand. `monitors.toml` lives on in `state/`. Strand's `monitors.lua` goes
too, so `hyprpier apply` writes its own. Remove `thunderbolt-resume.service` before reinstalling
hyprpier's resume service, or both would reset the controllers after every resume.

Docks enrolled in bolt can stay enrolled, since hyprpier's rule lets everything in anyway.
`boltctl forget <uid>` removes one.

`run_once_after_retire-hyprpier.sh` won't run a second time. To cut over again after a rollback,
run `bash ~/.local/share/chezmoi/run_once_after_retire-hyprpier.sh` yourself.
