# Chezmoi Dotfiles

Personal dotfiles managed with [chezmoi](https://www.chezmoi.io/).

## Theme System — Palette as Single Source of Truth

Palette JSONs in `dot_config/palette/` are the single source of truth for all theme colors.

```
Palette JSON          theme-switch          Theme Template           Chezmoi Template         Final Config
(palette/*.json) --> cp active.json    --> (*.theme)           --> (*.tmpl)             --> (~/.config/...)
                     (Quickshell instant)   [Jinja2: {< >}]         [Go: {{ }}]
                                            theme-switch            chezmoi apply
```

**Migration in progress (THM-2):** templated configs are being converted to chezmoi-native Go templates that read the palette directly — the `.tmpl` starts with `{{- $p := include "dot_config/palette/active.json" | fromJson -}}` and uses `{{ $p.<role> }}` plus filter helpers from `.chezmoitemplates/` (e.g. `{{ template "hypr_rgba" (list $p.base 0.8) }}`). These `.tmpl` files have **no `.theme` source** — edit them directly; theme-switch themes them via `chezmoi apply` alone. Converted so far: **yazi** (`theme.toml.tmpl`), **hyprlock** (`hyprlock.conf.tmpl`). Everything still listed under Theme Templates below remains on the Jinja pipeline.

Some apps have their config direct-written by `theme-switch` rather than fully templated — precise updates to specific keys, not full-file substitution:
- **Ghostty**: `_ghostty_theme` → writes `theme = ...` and `background-opacity = ...` to config
- **btop**: `_btop_theme` → writes `color_theme = ...` to config. Per-palette `.theme` files live in `dot_config/btop/themes/`.
- **pane-fm**: `_pane_fm_theme` → writes `theme = ...` and `light_icons = ...` to `config.toml`. Per-palette `.css` files live in `dot_config/pane-fm/themes/`.
- **Chromium/Chrome**: `_chromium_seed_color` + `_variant` → writes a managed policy JSON under `/etc/chromium/policies/managed/` (and the Chrome equivalent).

Zed is fully templated (`dot_config/theme-templates/zed/settings.json.theme` substitutes `_zed_theme_dark`/`_zed_theme_light`/`_variant` into `settings.json`), with per-palette Zed theme JSON in `dot_config/zed/themes/`.

**Hyprland** uses a Lua-require pattern (`hl.config({...})` API, 0.55+). `theme-switch` generates `dot_config/hypr/palette.lua` — a Lua module exposing role helpers like `p.surface0_rgba(0.93)`. `dot_config/hypr/hyprland.lua.tmpl` is edited directly (not generated — it does `local p = require("palette")`, so it needs no Jinja pass; its `{{ }}` blocks are real Go template conditionals for machine-specific GPU config). `hyprlock` stays on hyprlang, themed via a chezmoi-native template (see the migration note above); `hypridle` is a plain config with no templating.

### Palette Definitions (`dot_config/palette/`)

Catppuccin-style JSON files with named color roles:
- `everforest.json`, `catppuccin-mocha.json`, `rose-pine.json`, etc.
- `active.json` — copy of current theme (watched by Quickshell for live updates)

### Theme Templates (`dot_config/theme-templates/`)

Jinja2 templates with custom delimiters `{< >}` for apps still on the Jinja pipeline (gtk, phylax, zed settings, obsidian):
```css
background: {< background | rgba(0.9) >};
```

Available filters: `hex`, `hex_alpha(0.9)`, `rgba(0.9)`, `rgb`, `rgb_values`, `hypr_rgb`, `hypr_rgba(0.9)`, `strip`

`hyprland.lua.tmpl` is the exception — it has no `.theme` source; it uses `local p = require("palette")` and calls `p.<role>_rgba(opacity)` instead of Jinja tokens. See the Hyprland section above.

### Generated `.tmpl` Files

Build artifacts generated by `theme-switch` from `.theme` sources, committed to git so fresh clones work with a single `chezmoi apply`. Regenerated automatically when `theme-switch` runs. (Chezmoi-native `.tmpl` files — yazi, hyprlock, hyprland.lua — are *not* generated; edit them directly.)

### Chezmoi Templates

Standard chezmoi Go templates for machine-specific config (GPU drivers, hostname).

## Important: Editing Themed Files

If a config file has both `.theme` and `.tmpl` versions, **edit the `.theme` file** in `dot_config/theme-templates/`. The `.tmpl` file is generated and will be overwritten. If there is no `.theme` source (yazi, hyprlock, hyprland.lua), the `.tmpl` is the real source — edit it directly.

## Key Commands

```bash
# Switch themes (updates palette, generates templates, applies chezmoi, reloads apps)
theme-switch <theme-name>

# Apply chezmoi changes
chezmoi apply

# Preview changes
chezmoi diff
```
